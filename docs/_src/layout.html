Layout

Layout & styling

Open a container, add children, close it. Style the element you just made. Layout is a small flexbox: sizes flow up, width constraints flow down.

Building a tree

col()                 // open a vertical container
fill()                // ← modifiers style the LAST element: the col
gap(12.0)
    text("Title", 24.0)
    bold()            // ← the text
    row()
    gap(8.0)
        if button("OK") { set_int("ok", 1) }
        spacer()      // pushes what follows to the right edge
        if button_ghost("Cancel") { set_int("ok", 0) }
    end()             // closes the row; modifiers now target it
    padxy(0.0, 8.0)   // ← the row
end()
The one ruleModifiers apply to the last created element — or, right after end(), to the container it closed. Indentation is only for you.

Containers

children flowmain axiscross axis
col()top → bottomverticalhorizontal
row()left → righthorizontalvertical

The root is a column the size of the window. Elements without a fixed size take the size of their content plus padding.

Sizing

  • Content size — the default: text measures its shaped width and line height; containers sum their children along the main axis (plus gaps) and take the widest on the cross axis, plus padding.
  • Fixed — width(px), height(px), size(w, h).
  • Fill — fillw() / fillh() / fill(): along the parent's main axis it grows into free space; across it, it stretches.
  • Grow — grow(f): share of the free main-axis space, like CSS flex-grow.

Alignment

align(A_START | A_CENTER | A_STRETCH | A_END) places children on the cross axis. justify(J_START | J_CENTER | J_END | J_BETWEEN) distributes them on the main axis when nothing grows. center() sets both to center.

Wrapping text

col()
width(520.0)
pad(12.0)
gap(8.0)
    para("A long paragraph that wraps at spaces to whatever width its container gives it…", 14.0)
end()

para() wraps; text() never does. Because a paragraph's height depends on its width, measuring passes a width constraint down the tree (the container's fixed width or the window, minus padding). Wrapping is greedy at spaces, over glyph advances cached from HarfBuzz — re-wrapping unchanged text at a new width is cheap.

Long lists

first, cnt := vlist(100000, 40.0, state_f("scroll", 0.0))
k := 0
while k < cnt {
    i := first + k
    row()
    height(40.0)
    padxy(12.0, 0.0)
    align(A_CENTER)
    fillw()
        text("Item " + str(i), 13.0)
    end()
    k = k + 1
}
end()

vlist(n, row_h, scroll) opens a list filling its parent and returns the first visible row and how many to build. Build exactly those rows, each height(row_h). 100,000 rows cost what ~16 rows cost.

The theme constants (C_BG, C_SURFACE, C_TEXT, C_MUTED, C_ACCENT, C_BORDER) are at the top of framework/ui.src.

Painting order and culling

Elements are created in pre-order, so painting walks them in creation order: parents under children, later siblings over earlier ones. Anything entirely outside the window is skipped; wrapped text also skips lines below the window.

Clipping, scrolling, overlays

scroll_view("list")      // a clipped column that scrolls with the wheel while hovered
fill()
gap(4.0)
    // … as many children as you like …
end()

col()
clip()                   // children are clipped to this element's rect
    row()
    size(8.0, 8.0)
    radius(4.0)
    bg(C_DANGER)
    at(120.0, 4.0)       // out of the flow, pinned inside the parent's content box
    end()
end()

Clips nest (each intersects its parent's) and are applied per instance in the shader, so they cost no extra draw calls. A scroll view keeps its offset in the state store under its key and clamps it to last frame's content height.
