Method

The scenes are MyGo's comparison apps — the ones MyGo publishes against GPUI and egui. MyGo's app is its own benchmarks/mygo, built exactly as its docs build release apps. Ours is examples/bench, a line-by-line transcription: the same word generator (MyGo's LCG, bit for bit), the same cell values and colors, the same sizes, gaps and font sizes, windows of 360×260 and 800×600.

MyGo's runner measures on macOS only (proc_pid_rusage), so bench/run.py applies its method on Linux:

  • From outside the process via /proc: CPU = user + system time of every thread (framework, GL driver, GTK for MyGo) between the app's start and done, divided by frames; memory = RSS at rest and the peak (VmHWM).
  • From the app, the same stdout protocol for both: ready when the first frame is on screen (startup = process start → ready), start after 120 warmup frames, done {frames, wallUs, p50Us, p99Us, maxUs} after 600 measured frames, intervals timed at frame start.
  • Counter: 5 s after the first frame, RSS; then CPU over the next 5 s.
  • One unmeasured launch of each first; frameworks alternate order every round; medians.
Both on the GPUVerified, not assumed: MYGO_FRAME_STATS=all logs drawn on the GPU: 4133 instances in 1 batches for MyGo's grid. mdk draws its grid in one instanced call too.

How to read it

  • One laptop. On its own site (Apple M5, macOS) MyGo's grid is 5.7 ms/frame and its document 4.9 ms. Here its frame stats show where the time goes: layout 34–42 ms, 600 text layouts a frame in pure Go. mdk shapes text with HarfBuzz once and caches the run per (string, size, face); changed text is re-shaped, unchanged text is only re-broken into lines over cached advances. Expect the gap to shrink on faster CPUs — run it on yours.
  • Memory floor. An empty SDL3 + OpenGL window on this Mesa stack is already 66 MB, so mdk's own share at rest is ~11 MB. MyGo on Linux also carries GTK.
  • p99 ≈ 20 ms for both is this X11 compositor's jitter at 60 Hz.
  • Breadth is not measured. MyGo ships ~80 widgets, accessibility, IME, right-to-left, menus/tray/dialogs, a webview mode, installers and auto-update. mdk has boxes, flexbox, text, wrapping, buttons and a virtual list. This compares engines.

Reproduce

# MyGo's app, from a clone of github.com/egoist/mygo
CGO_ENABLED=0 go build -trimpath -tags mygo_noinspector \
  -ldflags "-s -w -X github.com/egoist/mygo.production=1" \
  -o /tmp/bench-mygo ./benchmarks/mygo

# mdk's, from this repo
./mdk build examples/bench -o build/bench-release

# about 10 minutes; windows open
DISPLAY=:0 python3 bench/run.py --mygo /tmp/bench-mygo --mdk build/bench-release \
  --runs 3 --out bench/results-linux.json

Look at any scene: MDK_SCENE=grid ./mdk shot examples/bench /tmp/g.ppm --size 800 600 --frames 30.
