Guide

Getting started

From a clone to a window in four commands, then the three ideas you need: the view runs every frame, state lives in the host, widgets return their events.

Install

You need machin ≥ 0.142 on your PATH (or in $MACHIN), a C compiler, cmake, the FreeType and HarfBuzz development packages, and OpenGL 3.3.

# Ubuntu / Debian
sudo apt install build-essential cmake pkg-config libfreetype-dev libharfbuzz-dev libgl-dev libx11-dev

git clone https://github.com/javimosch/machin-desktop
cd machin-desktop
./mdk dev examples/counter

The first run downloads SDL3 3.4.20 into vendor/ and builds it statically, video subsystem only (about a minute). Every later build reuses it.

Your first app

./mdk new apps/hello
./mdk dev apps/hello

mdk new writes apps/hello/app.src:

func view() {
    n := state_int("count", 0)
    col()
    fill()
    center()
    gap(16.0)
        text(str(n), 56.0)
        bold()
        row()
        gap(10.0)
            if button("Increment") { set_int("count", n + 1) }
            if button_ghost("Reset") { set_int("count", 0) }
        end()
    end()
}

Leave the window open, change 56.0 to 88.0 and save. The window redraws in place within a second; click a few times, change a color, save again — the count stays.

Three ideas

1. The view runs every frame

view() rebuilds the whole element tree each frame it runs — after input, a resize, a reload, or when you call animate(). There is no retained widget object to update: draw what the state says. An idle app runs no frames at all.

2. State lives in the host

Read and write values with state_int / set_int (also _f for floats and _str for strings). The store belongs to the host process, which is why it survives hot reloads. MFL globals reset when the module reloads — and must not be reassigned every frame (see the arena rule).

3. Widgets return their events

if button("Save") { set_str("status", "saved") }

A button is true on the frame the pointer is released over it after pressing on it. Hit-testing uses the previous frame's layout, so there's no callback registration and no event bus.

The dev loop

./mdk dev <appdir> watches every .src in the app and the framework. On save it runs machin encode (which typechecks), emits C, compiles a shared object (~0.5–1 s) and swaps it into the running window (0.3 ms). If machin rejects the edit, the error is drawn over the last good frame. Close the window with Esc.

Release builds

./mdk build apps/hello -o hello
./hello

The release links your app's C straight into the host: one binary (2.6 MB for the counter), no shared object, no reload checks, and it sleeps until an event — zero CPU at rest. It links FreeType, HarfBuzz and libGL from the system; SDL3 is static.

Commands

commandwhat it does
./mdk new <appdir>scaffold an app directory with app.src (a counter)
./mdk dev <appdir>build the app as a .so, open the window, rebuild on every save; the window and state survive; build errors draw over the last good frame
./mdk build <appdir> [-o out]one release binary with the app linked in (no reload, sleeps when idle)
./mdk shot <appdir> out.ppm [--size W H] [--frames N] [--click X Y]...render N frames (clicks are real SDL events) and save a screenshot; convert out.ppm out.png to view
./mdk check <appdir>typecheck the app with the framework (machin encode), no window
./mdk guideprint this JSON

Checking your work without a human

./mdk check apps/hello                                   # typecheck only
./mdk shot apps/hello /tmp/h.ppm --click 198 236           # real SDL click events, then a screenshot
convert /tmp/h.ppm /tmp/h.png                              # look at it

While mdk dev runs, kill -USR1 <mdk-host pid> saves the current frame to $MDK_SHOT (default /tmp/mdk-shot.ppm).
